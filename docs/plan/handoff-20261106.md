## 3. 架构基线（给不了解上下文的接手者）

### 3.1 `Policy` trait 与 union-deny 语义

- 判定入口是 `Policy` trait，默认实现 `CorePolicy`。engine 的授权调用点统一走 `Policy::decide`，不允许业务代码直接把 `evaluate_rules` 当唯一路径。
- 语义是 **`(floor ∪ grants) − deny`**：
  - `floor`：订阅/基础访问带来的允许；
  - `grants`：显式规则带来的允许；
  - `deny`：独立的 `[grants].deny` 列表，优先于前两者；
  - “规则匹配但缺少能力”不再自动构成 deny。
- `GrantRule.id` **必填**；重复 id 在启动期硬失败。`GrantDecision` 携带 `rule_id` 与 `policy_version`；core 校验 `rule_id` 非空、`policy_version` 与请求一致、`effect` 合法，不合法直接 deny。
- ticket 签发/校验、审计写入、能力枚举、fail-closed、break-glass 仍由 core 持有；`Policy` 只负责判定，不执行动作。
- 证据：
  - [policy.rs](file:///home/nixos/Documents/code/qq-bridge-fork/.agents/worktrees/qqab-arch/crates/kernel/src/policy.rs)
  - [grants.rs](file:///home/nixos/Documents/code/qq-bridge-fork/.agents/worktrees/qqab-arch/crates/kernel/src/grants.rs)（`GrantRule` 在 355 行，`id` 必填）
  - commit `12b1828`，以及 [acb-policy-store.md](file:///home/nixos/Documents/code/qq-bridge-fork/.agents/worktrees/qqab-arch/docs/design/acb-policy-store.md) §6.4、§11-P1。

### 3.2 75/78 退出码契约与三种后端

- `75`：回滚后强重启。systemd 用 `RestartForceExitStatus=75`；`acbctl run` 的父循环读到 75 后重读 `current.json` 重拉。
- `78`：终态放弃，不再重启。systemd 用 `RestartPreventExitStatus=78`；`acbctl run` 打印原因后退出。
- 三种后端并列：systemd（设计入口 `acb-launcher.service`）、`acbctl run`（launcher/direct）、容器（entrypoint 内保留 `acb-launcher`）。**systemd 不是必需底座**。
- 容器 runtime 无法区分 75/78，必须让 launcher 留在容器内消化，不能把裸 bridge 当 entrypoint。
- 现状差异：当前部署是 **systemd 直跑 `acb-bridge.service`**，不是 `acb-launcher.service`；只有 bridge 单元显式设置了 75/78，drivers/opencode/dsh 都是 `Restart=always`。设计中的 LKG/watchdog/launcher 路径没有部署。证据：[backend-capability-matrix.md](file:///home/nixos/Documents/code/qq-bridge-fork/.agents/worktrees/qqab-arch/docs/plan/backend-capability-matrix.md)，以及 `systemctl --user show acb-bridge -p RestartForceExitStatus -p RestartPreventExitStatus`。

### 3.3 profile 是二进制与 harness 脚本的版本入口

- 布局：`~/.local/share/acb/profile/generations/<gen>/root`，`current` 是相对软链，`switch` 只改这一条软链。
- Nix 只通过 `acbctl profile seed <store-path>` 做首次 bootstrap；之后版本由 ACB 自己 `profile add` + `profile switch` 管理。
- `seed` 语义：profile 为空时 `add + switch`；非空但 `current` 完好时打印 `seed skipped` 并退出 0；`current` 损坏且 payload 可用时重建一代并打印 `seed repaired current -> ...`。
- `profile switch` **不启停服务**，也不自动同步 `current.json`；要重启 unit 才吃到新 generation（或由 launcher 下次重拉）。
- `gc` 默认保留最新 5 个 + current + `../state/supervisor/lkg.json` 记录的 generation；label 不被单独保护。
- 当前运行态：

```text
source:  /nix/store/f38qgkgjjr88fzcqcrknsg3zvfl6rxh3-acb-profile-bootstrap
created: 2026-11-06 22:52:48
```

该产物里已 `grep` 到 `seed repaired current` 字符串和 `harnesses/shared/main-module.mjs`，说明 `1ea3b4a` 与 `b9c7d4b` 已经在 profile 内。`profile/current/bin` 有 `acb-bridge`、`acbctl`、`acb-issue-service`、`acb-launcher` 等，**没有 `acb-drivers`**；所以 drivers 仍走 nix wrapper，而不是 profile 里的二进制。

### 3.4 `acbctl` 实际子命令面

以本机 `acbctl --help` 为准（不要按记忆写）：

```text
acbctl unit render --print | --output-dir DIR | --diff --root DIR
acbctl unit install --root DIR
acbctl unit uninstall --root DIR
acbctl unit doctor --root DIR
acbctl run --mode=launcher|direct [--config PATH] [--state-dir DIR]
acbctl status --mode=run [--state-dir DIR] [--config PATH] [--health-url URL]
acbctl profile list|current|add|switch|gc|seed
acbctl grants explain|matrix|diff
```

两个容易写错的点：

1. **没有 `acbctl unit status`**。`unit` 只有 render/install/uninstall/doctor。
2. **`acbctl status --mode=run` 不是当前 systemd 栈的状态命令**。它读 supervisor 的 `run.json`/`current.json`/`lkg.json` 和 HTTP 探针，不调用 `systemctl`；当前部署没有 supervisor.toml，直接跑会报 `missing field supervisor`。看当前栈用 `systemctl --user` 或控制台 `/api/status`。

补充：PATH 上的 `acbctl` 来自 `/run/current-system/sw/bin/acbctl`（store 里的 `acb-bridge-0.1.0`）；它和 `profile/current/bin/acbctl` 的 sha256 相同（`334c0466...`），本轮两者都含 `1ea3b4a` 的 `seed repaired current`。以后如果 profile 先升级、store 后升级，这个“同哈希”假设就不成立，操作前先 `readlink -f $(command -v acbctl)`。

`grants explain/matrix/diff` 是本期唯一的只读判定 CLI，源固定为 config（`source=config:<base>+<config.d>`），`policy_version` 静态为 0；它们不是 live bridge 的实时判定。`diff` 支持两个不同来源文件对照（TOML/JSON/TSV）。

### 3.5 `config.d` 分片、`90-console.toml` 与迁 `policy.db` 的原因

- 加载顺序：base `config.active.toml` → `config.d/*.toml` 按文件名字典序 → `90-console.toml` 最后加载并覆盖它包含的顶层键。
- 若 `90-console.toml` 自带 `[grants]`，它会**整体替换**下层 `grants`，只有它自己的规则生效；解析器对此有专门判断，避免跨层重复。证据：[config.rs](file:///home/nixos/Documents/code/qq-bridge-fork/.agents/worktrees/qqab-arch/crates/kernel/src/config.rs) 1287–1340。
- 当前磁盘上是 base + `70-grants-issue.toml` + `80-issue-tools.toml`；`config.active.toml` 是派生文件，不是唯一源。现在有 10 条规则、6 个会话、1 个连接。
- **drivers wrapper 只读 base `config.toml` 的 session token，不读 `config.d`**（它只需要 sessions/harnesses；bridge 才读 `config.active.toml`）。改会话 token 时不要只改分片，否则 driver 仍拿旧值。证据：`/nix/store/0i2...-acb-drivers/bin/acb-drivers` 的 `session_token` 调用。
- 为什么必须迁 `policy.db`：控制台保存会再写一份 `90-console.toml`，文件分片、Nix 声明、`config.active` 派生文件会形成多份同一逻辑实体的数据；运行期改动缺少事务、版本和审计。设计目标是“同一逻辑实体的数据只允许出现在一个源里”，写操作走 policy API，bridge 独占写，`acbctl` 作为外部写者复用同一校验函数。
- 当前 `config.active.toml` 里仍有**明文会话 token**（本文档不复述）。迁移时按 `token_ref` 走 env/agenix，不把真值搬进库。

## 5. 尚未生效 / 尚未完成

### 5.1 需要一次 `switch` 才生效

- `10f3afbd`：四个用户单元的 `StateDirectory=acb`。当前 `/etc/systemd/user/acb-*.service` **没有** 这一行，只有 `ExecStartPre mkdir`。
- `6dd52426`：`/persist/home/nixos/.local/state/acb` 持久化。当前 `/persist` 下没有该路径；`/home/nixos/.local/state/acb` 只是当前 root 上的临时目录。
- `1fe2ac06`：mysecrets input bump；与 ACB 行为无关，是否随下次 switch 一起生效由用户决定。

**为什么急**：宿主机 root 是 impermanent，每次开机换 root subvolume，只有 preservation 里的路径保留。当前单元依赖 `ExecStartPre mkdir` 建日志目录，但 systemd 在 `ExecStartPre` 之前就会打开 `append:/home/nixos/.local/state/acb/*.log`；目录一旦在开机时不存在，单元会以 **209/STDOUT** 失败，`mkdir` 根本没机会执行。`10f3afbd` 用 `StateDirectory` 提前建目录，`6dd52426` 做持久化；两者都还没进运行态。当前能跑，是因为 22:54 启动时目录还在。

### 5.2 需要 profile 操作才生效

`nixos-rebuild switch` **不会**自动把新的 ACB bootstrap 加进 profile：`seed` 看到非空且 `current` 完好就 `seed skipped`。如果以后 acb input 再升级，正确顺序是：

```bash
acbctl profile add /nix/store/<new>-acb-profile-bootstrap --label <label>
acbctl profile switch <gen-or-label>
systemctl --user restart acb-bridge acb-drivers acb-opencode-serve
```

当前 profile 已经是 `b9c7d4b` + `1ea3b4a`，所以这次 switch 不需要再 `profile add`；但不要把“switch 会更新 ACB 版本”当成事实。

## 7. 硬约束（接手者必须遵守）

1. **clean core**：core 里出现业务语义词/业务分支（群运营、issue、通知、具体产品名、harness 名）即视为渗漏；只有“不变量 + 流水”允许留在 core。协议类型（`RoomId`、`Place::Group`、`Record`）不算渗漏。
2. **能做成插件的不放进 core**：harness 适配器、tool provider、通知派发、preset reconciler、其余业务策略都迁插件；`Policy` 的插件实现通过 trait 接入，`CorePolicy` 只是默认可替换实现。
3. **harness 无关、聊天平台无关的代码不许动**：core/kernel 不引入具体产品名；平台独有逻辑留在适配器/插件。
4. **允许破坏性变更，但不许减少功能面**：P1/P2 改造不得少功能；每个平台动作都必须有 op，风险靠分级/票据/审批管住，不能因为高危就不做。
5. **权限体系不做兼容层**：旧字符串写法、旧配置键（如 `allow_destructive`、`[connections.policy.risk]`）出现即启动失败，并给可抄的迁移示例；不做静默映射，不悄悄放大权限。
6. **构建要低强度**：`--cores 2 --max-jobs 1`、`nice -n 19`，一次只构建一个目标，不并行构建多个 derivation；默认不跑全 workspace 测试，只跑本次需要的目标。宿主机曾因内存耗尽把 GNOME 会话打掉，别用高并发构建。
7. **重任务串行**：同一时间只跑一个重任务；`cargo test --workspace` 全绿是提交门槛，但按上面的低强度方式串行执行。
8. **不修改上游文件以减少合并冲突**：优先在 ACB 侧新增/扩展，避免无必要地改上游实现。
9. **提交纪律**：一步一提交，clippy `-D warnings`，提交信息按仓库风格并带 `Assisted-by:` 尾注；不 `--no-verify`、不 amend；只推指定分支，不强制推送、不改历史。是否 push、何时 push 由用户确认。
10. **文档不写 token/密钥/明文凭证**：配置里的真值只引用路径或 env 名，不复述。

## 8. 常用操作

### 8.1 拉起 / 停止整栈

四个用户单元存在 `After/Wants` 关系：drivers `After=acb-bridge` 且 `Wants=dsh-acb`，opencode `After=acb-bridge`。手动按 **dsh → bridge → opencode → drivers** 的顺序最稳。

```bash
systemctl --user start dsh-acb
systemctl --user start acb-bridge
systemctl --user start acb-opencode-serve
systemctl --user start acb-drivers
```

停止（反向）：

```bash
systemctl --user stop acb-drivers acb-opencode-serve acb-bridge dsh-acb
```

```bash

sudo systemctl status acb-issue-service --no-pager
```

## 9. 踩过的坑

每条一句结论 + 一句教训。

1. **`driver.mjs` 用 `argv[1]` 与 `import.meta.url` 比较，遇 profile 软链会静默 exit 0。**
   - 教训：入口判定必须先 `realpath` 两侧，或由 wrapper 用 `readlink -f` 把真实路径传进去；否则 unit 会每 `RestartSec` 空转，日志里没有报错。
   - 证据：`b9c7d4b`、`4a0fb0e3`、[main-module.mjs](file:///home/nixos/Documents/code/qq-bridge-fork/.agents/worktrees/qqab-arch/harnesses/shared/main-module.mjs)。

2. **`ExecStartPre mkdir` 晚于 `append:` 日志打开，导致 209/STDOUT。**
   - 教训：`StandardOutput/StandardError=append:` 在 `ExecStartPre` 之前就打开文件；日志目录必须由 `StateDirectory=` 或更早的机制创建，不能只靠 `ExecStartPre mkdir`。
   - 证据：`10f3afbd` 的提交说明、[preservation.nix](file:///home/nixos/nix-config/hosts/idols-ai/preservation.nix#L185-L188)。

3. **impermanent root 让 `~/.local/state/acb` 每次开机消失。**
   - 教训：宿主 root subvolume 每次开机换新，只有 preservation 列出的路径保留；日志/状态目录必须进 preservation，且 `StateDirectory` 只能当兜底，不能当持久化。
   - 证据：`6dd52426`；当前 `/persist/home/nixos/.local/state/acb` 不存在。

4. **旧二进制 `deny_unknown_fields` 不容忍新 `GrantRule.id`。**
   - 教训：给 grants 加必填字段时，旧 bridge 会在解析期直接拒绝整份配置；升级必须先换 profile/二进制再改配置，或一次 switch 同时完成。不要以为 serde 会忽略未知字段。
   - 证据：[grants.rs](file:///home/nixos/Documents/code/qq-bridge-fork/.agents/worktrees/qqab-arch/crates/kernel/src/grants.rs#L354-L364)、`config.rs` 的 `deny_unknown_fields`。

5. **工具沙箱的 `findmnt`/`ps` 会撒谎（UID 65534、ro mount 是假象）。**
   - 教训：issue service 的 `ps` 显示 `nobody` 是旧 invocation 残留；`/var/lib/acb-issue` 在宿主机是 rw，沙箱里读成 ro 是误导。判断以 `systemctl show`（`User`/`MainPID`/`StateDirectory`）和宿主机实际挂载为准，不要用沙箱里的进程/挂载快照下结论。
   - 证据：项目运维记忆中的复盘记录；仓库文档没有收录这条，按“未验证于仓库”对待。

6. **`git commit -- <paths>` 会把工作树里未暂存的改动一起带走。**
   - 教训：提交前先 `git add` 精确路径，再 `git commit`；不要用 `git commit -- path` 顺手提交，否则会把还没准备好的改动夹带进去。
   - 证据：git 行为本身；本项目此前出现过同类误提交。
